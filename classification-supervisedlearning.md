# Classification - Supervised ML: Email Spam Detection

Classifies each incoming email as **spam** or **ham (not spam)** based on content, sender patterns, and structural signals learned from labelled examples.

---

## What is Classification?

Classification is a supervised learning task where the model learns a mapping from input features to a **discrete class label**.

| Concept | This Project |
|---|---|
| Input (X) | Email subject, body text, sender address |
| Output (y) | `1` = spam, `0` = ham |
| Algorithm family | Binary classification |
| Supervision | Labelled emails (spam/ham) used during training |

## Feature Engineering

Two types of features are combined into a single sparse matrix:

### 1. TF-IDF Text Features (15,000 features)
Extracts vocabulary patterns from `subject × 2 + body` (subject weighted double).

| Setting | Value | Reason |
|---|---|---|
| `ngram_range` | (1, 2) | Captures phrases like "click here", "act now" |
| `sublinear_tf` | True | Dampens high term frequencies (spam repeats words) |
| `stop_words` | English | Removes uninformative common words |
| `max_features` | 15,000 | Limits memory while keeping discriminative vocabulary |

### 2. Handcrafted Numeric Features (19 features)

| Feature | What it measures |
|---|---|
| `caps_ratio` | Proportion of uppercase characters |
| `exclamation_ratio` | Exclamation marks per word |
| `question_ratio` | Question marks per word |
| `url_count` | Number of URLs in the email |
| `embedded_email_count` | Email addresses mentioned in body |
| `dollar_count` | Dollar sign occurrences |
| `digit_ratio` | Proportion of digit characters |
| `html_density` | HTML tag density (spam often hides links in HTML) |
| `spam_keyword_count` | Count of known spam trigger words |
| `is_html` | Email rendered as HTML |
| `sender_free_domain` | Sender uses free provider (gmail, yahoo, etc.) |
| `sender_suspicious_domain` | Sender domain ends in .xyz, .top, .click, .loan, etc. |
| `sender_no_domain` | Sender has no @ domain |
| `subject_empty` | Subject line is blank |
| `subject_all_caps` | Entire subject in uppercase |
| `subject_has_re_fwd` | Subject starts with Re: or Fwd: (signals legitimacy) |
| `subject_exclamation_count` | Exclamation marks in subject |
| `avg_word_length` | Average word length |
| `body_length_normalized` | Normalised body word count (capped at 1000 words) |

All numeric features are MinMax-scaled to `[0, 1]` before being appended to the TF-IDF sparse matrix.

## Classification Algorithms Compared

Five classifiers are trained and evaluated via **Stratified 5-Fold Cross-Validation**. The one with the highest F1 score is saved.

| Algorithm | Strengths for spam detection |
|---|---|
| **Logistic Regression** | Strong baseline for text; fast; probabilistic output |
| **Complement Naive Bayes** | Designed specifically for imbalanced text classification (spam/ham) |
| **Random Forest** | Captures non-linear feature interactions; robust to outliers |
| **Gradient Boosting** | High accuracy; handles mixed feature types well |
| **Calibrated SVM** | Excellent text classifier; calibration adds probability estimates |

### Evaluation Metrics

| Metric | Formula | Why it matters for spam |
|---|---|---|
| **Precision** | TP / (TP + FP) | Low precision = legitimate emails marked as spam |
| **Recall** | TP / (TP + FN) | Low recall = spam emails reaching the inbox |
| **F1 Score** | 2 × P × R / (P + R) | Balances both; used to select best model |
| **ROC-AUC** | Area under ROC curve | Threshold-independent performance measure |

## Response Field Reference

| Field | Type | Description |
|---|---|---|
| `is_spam` | bool | `true` if classified as spam |
| `spam_probability` | float 0–1 | Model's confidence it is spam |
| `ham_probability` | float 0–1 | Model's confidence it is not spam |
| `confidence` | string | `high` / `medium` / `low` — how decisive the model is |
| `risk_level` | string | `critical` (≥0.85) / `high` (≥0.65) / `medium` (≥0.40) / `low` |
| `spam_signals` | list | Human-readable signals that triggered (rule-based explainer) |
| `inference_time_ms` | float | Per-email latency in milliseconds |

### Spam Signals Glossary

| Signal | Triggered when |
|---|---|
| `excessive_capitalization` | >25% of characters are uppercase |
| `excessive_exclamation_marks` | More than 3 `!` in the email |
| `multiple_urls` | More than 2 URLs in the body |
| `heavy_monetary_language` | More than 2 `$` signs |
| `urgency_language` | Phrases like "act now", "limited time", "claim now" |
| `money_offer_detected` | Phrases like "free money", "prize", "lottery", "winner" |
| `phishing_pattern` | Phrases like "verify your account", "account suspended" |
| `subject_all_caps` | Subject line is entirely uppercase |
| `subject_excessive_punctuation` | More than 1 `!` in the subject |
| `suspicious_sender_domain` | Sender domain ends in `.xyz`, `.top`, `.click`, `.loan`, etc. |
| `heavy_html_content` | HTML email with more than 20 HTML tags |

## How Supervised Learning Works Here

```
Labelled emails (subject, body, sender, label)
        |
        v
EmailFeatureExtractor.fit(X_train)
  ├── TfidfVectorizer learns vocabulary from training corpus
  └── MinMaxScaler learns min/max of each numeric feature
        |
        v
Cross-validate 5 classifiers on extracted features
        |
        v
Best classifier (by F1) refitted on full training data
        |
        v
Pipeline saved: featurizer + classifier
        |
        v
At inference: new email → same transform → predict_proba → verdict
```

The key supervised learning insight: the model never sees hand-coded rules for what makes something spam. It learns purely from the **statistical patterns** in labelled examples — which words co-occur with spam labels, which numeric feature combinations predict spam, etc.
